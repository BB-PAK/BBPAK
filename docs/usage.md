# 실제 사용 흐름

## 1. 작업할 프로젝트를 고릅니다

이 초기 버전에는 비비팍님의 반복 작업에 맞춘 기본 제작 규칙이 들어 있습니다. 사용자의 승인에 따라 지침과 도구를 공개하며, 특정 작품의 시나리오 원문과 캐릭터 이미지 원본은 포함하지 않았습니다. 프로젝트마다 별도 프로필 JSON을 작성하거나 `--profile` 없이 빈 프로젝트로 시작하세요.

## 2. 원문과 참조를 연결합니다

`scripts/new_project.py` 실행 후 생성된 `script-source.md`에 실제 확정 시나리오를 넣고 출처·버전을 적습니다. `references.json`에 캐릭터 시트, 마스터 화풍, 공간 참조의 위치와 확인 상태를 적습니다. AI에게 읽을 수 있는 파일을 직접 제공하거나 접근 가능한 위치를 알려줍니다. 링크를 적었다고 접근 권한까지 생기지는 않습니다.

승인 상태는 사람이 실제로 승인한 뒤에 바꿉니다. 초기값 `missing_source`, `unverified`, `draft`는 작업자가 자료를 확인하도록 남겨둔 상태입니다.

## 3. 필요한 스킬만 사용합니다

전체 순서를 잡을 때 제작 진행 스킬을 사용하고, 한 장면의 프롬프트만 필요하면 그 스킬부터 시작합니다. 이미 확정한 단계를 매번 다시 승인받지 않습니다.

프롬프트는 `prompt-image-v001.md`, `prompt-video-v001.md`에, 검수는 `review-v001.md`에 기록합니다. 수정할 때는 `v002`처럼 새 파일을 만들어 승인본과 실패본을 함께 남깁니다. 자동 생성 스크립트는 버전 승격이나 승인 처리를 하지 않습니다.

## 4. 생성 서비스에서 실행합니다

프롬프트 지침은 생성 모델 자체가 아닙니다. 사용 중인 서비스에 참조 이미지를 첨부하고 프롬프트를 입력해야 합니다. 서비스의 업로드 파일과 프롬프트의 참조 표기가 서로 맞는지 확인합니다.

예를 들어 `@image1`이라는 문자는 모든 서비스의 공통 문법이 아닙니다. 제공자가 지원하는 표기 방식으로 바꾸되 참조 역할은 유지합니다.

## 5. 결과를 확인합니다

이미지는 원본을 직접 보고, 영상은 재생과 필요한 시각의 프레임을 함께 확인합니다. 음향 평가는 직접 청취한 구간만 작성합니다. `inspect_video.py`로 만든 프레임에는 선택된 실제 시각이 JSON에 기록되지만, 프레임 사이의 동작은 알 수 없습니다.

손가락 하나가 어색한 경우 전체 화풍을 바꾸기보다 해당 동작과 구도를 먼저 수정합니다. 오디오에 문제가 있으면 영상 전체를 다시 생성하기 전에 후반 작업으로 해결 가능한지 판단합니다.

## 다른 제작 분야로 확장할 때

BBDesign 소개 영상이나 SNS 광고는 별도 프로젝트 프로필로 확장할 수 있습니다. 현재 저장소에는 광고 자동 편집·웹사이트 캡처·모션그래픽 렌더러가 구현되어 있지 않습니다. 실제로 반복되는 작업이 생기면 그때 작은 스킬부터 추가합니다.
